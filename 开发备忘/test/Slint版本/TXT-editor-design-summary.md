# TXT 编辑器 — MVP 设计总结

> 用途：作为动手写 Rust 代码前的思路整理文档，记录已确定的产品定位和技术决策。

## 产品定位

- 目标：成为普通用户电脑上的**默认轻量文本编辑器**，对标"系统自带记事本"的替代品，而非开发者向的重型编辑器。
- 核心原则：**最大公约数，最小不必要功能**。做绝大多数人真正需要的事，不做锦上添花的复杂功能。
- 技术栈：Rust + Slint（GUI）+ Rope 结构文本缓冲区。
- 体验优先级：轻量、高性能、多标签、纯文本、**极少打扰用户**。

---

## MVP 功能范围

| 功能 | 是否包含 | 说明 |
|---|---|---|
| 多标签编辑 | ✅ 必须 | 基本能力 |
| 纯文本约束 | ✅ 必须 | 粘贴富文本/HTML 时自动剥离格式，只保留纯文本 |
| 关闭标签无弹窗提示 | ✅ 必须 | 不打断用户，交给自动保存机制兜底 |
| 重开软件恢复标签 | ✅ 必须 | 见下方"持久化与恢复机制" |
| 语法高亮 | ❌ MVP不做 | 后续版本再考虑，避免与大文件性能优化叠加导致复杂度暴涨 |
| 缓存加密 | ✅ 保留，但用简单方案 | 见下方"缓存加密方案" |

## 持久化与恢复机制（核心设计）

### 设计哲学
**后台默默做好，绝不弹窗问用户"要不要保存"。** 唯一允许出现的提示是真正涉及数据丢失风险的场景，且必须是非阻塞的轻量提示（如状态栏文字、标签角标），不能是弹窗。

### 分两类标签处理

**1. 已保存过的标签（关联真实磁盘文件）**

- 编辑内容后，**防抖（debounce，建议 1–2 秒无操作后触发）** 自动写入磁盘。
- 写入方式：**原子写**（先写临时文件，再 rename 替换原文件），避免进程崩溃导致文件写坏一半。
- 磁盘文件始终视为该标签的"最新真相"。
- 软件重开时，直接从磁盘读取文件最新内容展示。

**2. 未保存过的标签（纯临时草稿，不对应任何文件）**

- 内容变化后静默写入本地加密缓存。
- 软件重开/崩溃恢复后，从缓存原样还原标签内容。

### 外部修改冲突处理

场景：软件准备自动保存时，发现磁盘上的文件已被外部程序（如其他编辑器、Git、脚本）改动过。

处理方式：
1. **跳过这次自动覆盖**，不覆盖外部修改的内容。
2. 把当前应用内的编辑内容转存为**冲突缓存副本**（本地加密缓存里的一份"待处理"记录）。
3. 用非阻塞的轻量方式提示用户（如标签角标变化、状态栏一行小字："检测到外部修改，你的更改已保存为副本"），不弹窗打断操作。
4. 用户可以自行决定何时查看/合并这份冲突副本，软件不强制处理。

### 需要注意的实现细节
- 检测外部修改：记录文件的 mtime 和/或内容哈希，写入前对比。
- 原子写的临时文件也必须是**加密写入**，不能先写明文再加密替换，否则会有短暂的明文残留窗口。
- 标签正常关闭后，应清理该标签对应的加密缓存文件，减少残留。

## 缓存加密方案

### 威胁模型（明确边界，避免过度设计）

- **目的**：防止用户不小心把密码、密钥等敏感信息粘贴到临时标签里时，被其他运行在同一台电脑上的恶意软件直接读取明文缓存。
- **不追求**：军规级安全、防御拥有当前用户完整权限的攻击者（这超出编辑器该负责的范围）。

### 技术方案（简单、不臃肿）

| 组件 | 选型 | 说明 |
|---|---|---|
| 密钥存储 | `keyring` crate | 调用系统原生密钥库：Windows Credential Manager / macOS Keychain / Linux Secret Service。首次启动生成随机密钥并存入，之后直接读取。**全程无需用户设置密码，无任何加密相关 UI**。 |
| 加密算法 | AES-256-GCM（`aes-gcm` crate） | 现代 CPU 普遍有 AES-NI 硬件加速，加解密几百 KB～几 MB 的草稿耗时是毫秒级，不影响自动保存体验。 |

### 实现建议
- 按标签/草稿为单位加密，不要把整个缓存目录打包成一个大文件，方便按需解密单个标签。
- 内存中解密后的明文生命周期尽量短（无法完全避免，属于操作系统层面的问题，超出本项目威胁模型）。
- 正常关闭标签后要清理对应缓存文件；不需要做多次覆写式的安全擦除（超出威胁模型要求）。

## 建议的下一步（代码实现顺序）

1. **编辑核心**：基于 rope 结构（如 `ropey`）实现基本的增删改、光标、选区。MVP 阶段文件不会很大，也可以先用简单方案，后续替换。
2. **会话持久化模块**：这是本项目和"普通文本框"的本质区别，建议优先搭建数据结构和状态机（标签状态、文件关联、脏标记、冲突标记）。
3. **加解密模块**：`keyring` + `aes-gcm` 的集成，作为持久化模块的底层支撑。
4. **Slint 多标签 UI**：标签栏、文本编辑区、打开/另存为对话框。
5. **纯文本粘贴处理**：剪贴板读取时过滤富文本/HTML。
6. **跨平台打包**：Windows/macOS/Linux 基本可运行的安装包。

语法高亮、大文件专项性能优化，留到 MVP 验证之后再评估是否要做、做到什么程度。
