# FinchPad 标签状态与生命周期决策矩阵 v1.1

> **文档说明**：本文档定义了 FinchPad 各类标签在不同磁盘状态下的缓存策略、恢复逻辑与前端交互规范。是后续开发与维护的核心准则。
> 
> **版本**：v1.1（最终定稿）
> **更新日期**：2024-05-24

---

## 一、 核心设计原则

1. **尽可能不丢失工作**：缓存是保证内容不丢失的生命线。只要缓存存在，就必须让用户看到内容，绝不静默清空。
2. **极致轻量化**：大文件不缓存、不恢复；利用 `cache_stale` 机制大幅降低无意义磁盘 I/O。
3. **数据安全第一**：路径不可达或被删除时，禁止覆盖空内容。强制引导用户另存为，防止因误操作导致原路径数据损坏。
4. **拒绝僵尸状态**：没有缓存且磁盘不可达的标签，直接丢弃，绝不保留无意义的空标签。

## 二、 标签状态矩阵

### 1. 未命名标签（无 `file_path`）
*特点：无磁盘参照物，内容完全依赖内存与缓存。*

| 状态 | 标签栏 / 状态栏 | 缓存策略 | 会话恢复逻辑与边界情况 | 前端渲染 |
| :--- | :--- | :--- | :--- | :--- |
| **空 + 干净** | `未命名1` / 干净 | **不缓存** | 不写入 session。重启时直接生成一个全新的空白标签。 | 正常渲染空白 Monaco |
| **有内容 + 脏** | `未命名1 ●` / 脏 | **必须缓存**（`cache_stale` 触发，周期+退出） | 读缓存恢复内容，标为脏。关闭时必弹窗询问保存。 | 正常渲染 Monaco |

### 2. 已命名标签 —— 普通文件（< 50MB）
*特点：有磁盘参照物，采用 `cache_stale` 优化缓存频率，严格防止数据覆盖。*

| 状态 | 标签栏 / 状态栏 | 缓存策略 | 会话恢复逻辑与边界情况 | 前端渲染 |
| :--- | :--- | :--- | :--- | :--- |
| **干净 + 磁盘正常** | 正常 / 干净 | `cache_stale` 触发。第一次 tick 写一次，之后跳过。退出时若已缓存，严格跳过。 | 优先读缓存。对比磁盘哈希：一致则标干净；不一致则**标为脏，状态栏显示 `modified`**。**当此标签变为激活状态时，弹窗让用户选择（重载磁盘 / 保留缓存）。** | 正常渲染 Monaco |
| **脏 + 磁盘正常** | `●` / 脏 | `cache_stale` 触发。周期写入（<10MB 每秒，10-50MB 每 60 秒）+ 退出写入。 | 读缓存恢复内容，标为脏。当标签变为激活状态时，弹窗让用户选择。 | 正常渲染 Monaco |
| **干净/脏 + 磁盘被删除**（父目录在） | 正常 / `deleted` | 同上（`cache_stale` + 周期 + 退出） | 缓存存在 → 读缓存恢复内容，状态栏显示 `deleted`。保存时直接跳转另存为。<br>缓存不存在 → **直接丢弃标签**。 | **正常渲染 Monaco**（展示缓存内容） |
| **干净/脏 + 磁盘不可达**（父目录不在） | 正常 / `unreachable` | 同上（`cache_stale` + 周期 + 退出） | 缓存存在 → 读缓存恢复内容，状态栏显示不可达提示。保存时直接跳转另存为。<br>缓存不存在 → **直接丢弃标签，不要空标签**。 | **正常渲染 Monaco**（展示缓存内容） |

### 3. 已命名标签 —— 大文件（≥ 50MB）
*特点：**绝对不缓存、不恢复、不弹窗提醒崩溃丢失**。极简处理，性能优先。*

| 状态 | 标签栏 / 状态栏 | 缓存策略 | 会话恢复逻辑与边界情况 | 前端渲染 |
| :--- | :--- | :--- | :--- | :--- |
| **未加载（Pending）** | 正常 / 懒加载 | **不缓存** | 写入 session。重启后：磁盘可达 → pending；不可达 → **直接丢弃标签**。 | 渲染空白 Monaco + Pending 覆盖层 |
| **已加载 + 干净** | 正常 / 干净 | **不缓存** | 写入 session。重启后：磁盘可达 → 回退为 pending；不可达 → **直接丢弃标签**。 | 正常渲染 Monaco |
| **已加载 + 脏** | `●` / 脏 | **不缓存** | 写入 session。关闭时必弹窗询问保存。若崩溃，内容丢失，**完全静默处理，不弹窗告知**。重启后：磁盘可达 → pending；不可达 → **直接丢弃标签**。 | 正常渲染 Monaco |

## 三、 关键机制与行为规范

### 1. 缓存失效标志位 `cache_stale`
为了减少无意义的磁盘 I/O，在 `Tab` 结构体中引入 `cache_stale: bool`：
- **置 `true`（需要缓存）**：新建标签、编辑内容、保存文件、重载内容、恢复会话时。
- **置 `false`（无需缓存）**：`write_cache` 成功执行后。
- **检查逻辑**：`tick_autosave` 和 `save_and_prepare_exit` 中必须检查 `if (!tab.cache_stale) continue;`。
- **退出清理**：即使 `cache_stale = false`，也必须将该标签的 `id` 推入 `keep_ids`，防止被当作孤儿缓存清理。

### 2. `Ctrl+S` 拦截与另存为引导
当标签处于 `needs_reload = true`（不可达占位）或 `disk_state = "deleted"` 时：
- **后端**：`save_active_file` 检测到状态异常，直接返回特定的错误 `Err("NeedsSaveAs")`。
- **前端**：`+page.svelte` 的 `handleSave` 必须捕获该错误，并**静默将其导向 `handleSaveAs()`**，绝对不允许将空内容写回原路径。

### 3. 编辑器与状态栏渲染规范
- **`Editor.svelte`**：不需要增加 `needsReload` 属性或覆盖层。只要 `value` 有内容（即使是缓存内容），Monaco 就必须正常渲染。
- **`StatusBar.svelte`**：外部修改的警告判断条件改为 `diskState === 'modified'`（不再需要 `&& isDirty` 判断），因为文件被外部修改时会主动标记为脏。
- **不可达提示**：状态栏显示 `unreachable` 或 `deleted` 警告。用户如需重新从磁盘同步，可点击状态栏警告文字触发 `api.reloadTab(idx)`，或者手动重新打开文件。

### 4. 恢复时的脏状态判定（防止误标脏）
在 `restore_one_tab` 中：
- 若从缓存恢复，**不能**无条件将 `is_dirty` 标为 `true`。
- 应读取磁盘内容，与缓存内容进行哈希比对。若磁盘可达且哈希一致，恢复为**干净**状态；若不一致，恢复为**脏**状态并标记 `disk_state = 'modified'`。
- 若磁盘不可达，则保持 session 中记录的 `is_dirty` 状态（若为 `true` 则保持脏；若为 `false` 则标记为 `unreachable` 但内容干净）。

## 四、 恢复时的优先级策略流

对于任何有路径的标签（已命名）：
1. **第一顺位：读取缓存（Cache）**。
   * 命中缓存 → 用缓存内容还原 `buffer`。
   * 尝试读取磁盘。若磁盘可达 → 哈希比对决定干净/脏（并显示 `modified`）；若磁盘不可达 → 保持当前状态，标记 `unreachable`。
2. **第二顺位：无缓存，读磁盘**。
   * 磁盘可达 → 正常读入。如果大小 ≥ 50MB，转为 pending 懒加载状态。
   * 磁盘不可达（文件被删除或父目录不可达）→ **直接返回 `None` 丢弃标签**。

对于未命名标签（无路径）：
1. 有缓存 → 恢复内容，标为脏。
2. 无缓存 → 直接丢弃（内容已丢失，无从恢复）。
